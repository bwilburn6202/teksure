# TekSure Redundancy Audit — 2026-08-30

Nothing in this report has been deleted. Every item is a proposal with the evidence
that produced it. Approve by tier, or line by line.

**Headline:** the repo is ~1.6 GB, of which **~510 MB is stale build output** that git
already ignores. The website's real problem is different: **2,970 `/tools/*` pages, of
which 2,246 are under 300 words and 2,480 have no editorial inbound link** — the same
"4,000 mediocre pages" pattern the guide-count target was retired over on 2026-08-04,
except it was never cleaned up at the route layer.

## Tier 3 — The real one: the `/tools` surface. User-visible, needs your call.

### The numbers

| Measure | Count |
|---|---|
| `/tools/*` routes | 2,970 |
| Page files in `src/pages/tools/` | 2,960 (24 MB) |
| Under 300 words of visible text | **2,246** (median page: 210 words) |
| Files ≤35 lines (single-line-per-card stubs) | 1,156 |
| Files >400 lines (genuine interactive tools) | 97 |
| No inbound link outside the auto-generated directory | **2,480** |
| Submitted to Google in `sitemap.xml` | 2,957 |

### What a typical page actually contains

`AAAAppForSeniorEmergency.tsx` — 29 lines, six cards of three-word bullets:
"Free.", "Senior peace.", "Worth it." The bullet "free." appears verbatim on **190
different pages**; "senior easy." on 47.

### The duplication inside it

207 near-duplicate topic clusters covering 443 pages. Same topic, three URLs:

- `senior-telehealth` / `senior-telehealth-basics` / `telehealth-basics` / `telehealth-for-seniors`
- `senior-vpn` / `senior-vpn-guide` / `vpn-guide` / `vpn-for-seniors-explained`
- `ev-charging-apps` / `ev-charging-basics` / `ev-charging-for-seniors` / `senior-ev-charging-apps`
- `chatgpt-for-seniors` / `senior-chatgpt` / `senior-chatgpt-basics`

These compete with each other in search. Collapsing each cluster to one page removes
~236 URLs before any quality judgment is applied.

### Why this is worth doing beyond tidiness

1. **It is the stated policy.** Quality over count, decided 2026-08-04. That decision
   was applied to guides and never to tool pages.
2. **Thin, templated, orphaned pages are what Google's helpful-content system
   demotes** — and 2,957 of them are in the sitemap, next to the ~250 pages that are
   genuinely good. The weak ones dilute the strong ones.
3. **It is the build-OOM blocker.** `prebuild` prerenders 7,128 URLs. Cutting to
   ~1,500 makes the build finish.
4. **97 real interactive tools** — `AccessibilityCheck`, `BluetoothPairingHelper`,
   `RemoteControlDecoder`, `KitchenTechHelper` — are currently indistinguishable from
   2,873 stubs in a 2,969-row directory. The good work is buried by the filler.

### Proposed cut

Keep ~250 `/tools` pages: the 97 interactive tools plus the 156 pages over 1,000
words. Redirect the remaining ~2,700 slugs to the nearest surviving tool or guide
(`scripts/generate-redirects.mjs` already exists), drop them from the sitemap, and
delete the components. This takes `src/pages/tools` from 24 MB to roughly 3 MB.

### And then `App.tsx` shrinks on its own

7,445 lines / 612 KB, containing 3,098 hand-written `lazy()` declarations and 3,156
`<Route>` entries. After the cut, the remaining tool routes should be generated from
`tools-directory.ts` rather than hand-listed — one `<Route path="/tools/:slug">` with a
lookup. That is what makes the file stop growing by hand and stop accumulating the
duplicate routes in 2d.

visitor sees. Step 3 is the one that changes the website.
